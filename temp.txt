# Stayable --- Project Context

## 1. Project Overview

**Stayable** is a student accommodation discovery platform focused on
helping students quickly find **PGs (Paying Guest accommodations) and
Flats near their college**.

The platform is designed around a **college-centric location
experience**:

> Student selects/scans a college QR code → sees nearby PGs and Flats on
> a real map → opens a property → checks details → contacts the owner or
> gets directions.

Stayable is intended to be simple for students and easy for property
owners/admins to manage.

------------------------------------------------------------------------

## 2. Main Goal

The main goal of Stayable is to solve the problem of students struggling
to find suitable accommodation near their college.

Students should be able to:

-   Select their college.
-   See nearby PGs and Flats.
-   View them on a real map.
-   Compare rent, distance, facilities and reviews.
-   Open complete property details.
-   Call or WhatsApp the owner.
-   Get directions.
-   Save properties for later.

Property owners should be able to:

-   Create an account.
-   Add PGs and Flats.
-   Add photos, rent, facilities and room/property information.
-   Select their exact property location using Google Maps.
-   Receive enquiries.
-   Manage their listings.
-   View basic analytics and reviews.

Admins should be able to:

-   Manage colleges.
-   Manage PGs.
-   Manage Flats.
-   Manage owners and students.
-   Manage reviews and enquiries.
-   Manage college/area QR codes.
-   View reports and platform activity.

------------------------------------------------------------------------

# 3. Core USP

The key USP of Stayable is a **college-centric real-world map**.

Instead of making students search through a generic property listing,
Stayable starts from the student's college.

Example:

``` text
MIT-WPU
   ↓
Real Google Map
   ↓
Nearby PGs + Flats
   ↓
Distance / Rent / Facilities
   ↓
Property Details
   ↓
Call / WhatsApp / Directions
```

The map should show:

-   College location.
-   Nearby PG markers.
-   Nearby Flat markers.
-   Roads.
-   Buildings/landmarks available through Google Maps.
-   Distance from college.
-   Property rent.
-   Selected property state.

# 8. Google Maps Integration

The simulated beige map currently used in the prototype should be
replaced with a real Google Maps JavaScript API map.

The Google Maps implementation should use:

-   Google Maps JavaScript API.
-   Google Maps API key from environment variables.
-   Google Map ID.
-   Modern `AdvancedMarkerElement`.
-   Place search/autocomplete for owner location selection.
-   Real latitude/longitude for college and property locations.

Environment variables:

``` env
VITE_GOOGLE_MAPS_API_KEY=YOUR_GOOGLE_MAPS_API_KEY
VITE_GOOGLE_MAP_ID=YOUR_GOOGLE_MAP_ID
```

Never hardcode the API key in source code.

Never commit `.env.local` to GitHub.

For production, the Google API key should be properly restricted.

6.  Allow users to zoom and move around.
7.  Allow clicking property markers.
8.  Selecting a marker should select the corresponding property card.
9.  Selecting a property card should highlight the corresponding map
    marker.
10. Show rent on/near property markers where practical.

13. Recenter/update when the selected college changes.

Avoid the deprecated:


Prefer:

``` text
google.maps.marker.AdvancedMarkerElement
```

``` text
student
```

# 28. Security Requirements

Never:

-   Commit `.env.local`.
-   Hardcode API keys.
-   Put Supabase service-role keys in frontend code.
-   Trust frontend role checks as database security.
-   Give owners access to other owners' properties.
-   Allow students to modify protected owner/admin data.

Use:

-   Supabase Auth.
-   Supabase RLS.
-   Proper ownership checks.
-   Restricted Google API keys.
-   Environment variables.

# 34. Implementation Rule for Future Changes

When modifying Stayable:

1.  Preserve existing functionality.
2.  Avoid unnecessary redesigns.
3.  Do not remove PG functionality when adding Flats.
4.  Do not break authentication.
5.  Do not break Supabase integration.
6.  Do not expose secrets.
7.  Keep the UI responsive.
8.  Use reusable React components.
9.  Use real database data instead of hardcoded production data.
10. Test desktop and mobile after major UI changes.
11. Keep map functionality isolated from unrelated features.
12. Prefer production-ready architecture over temporary hacks.

        check.classList.remove('text-on-primary');

    button.classList.remove('bg-surface-container-lowest', 'text-on-surface');

    if (activeIcon) {
      activeIcon.classList.remove('text-outline');

    const activeCheck = button.querySelector('.material-symbols-outlined:last-child');
    if (activeCheck) {
      activeCheck.textContent = 'check_circle';
      activeCheck.classList.remove('text-outline', 'opacity-40');
    }

  // Filter Tabs Micro-Interaction

      const filter = button.getAttribute('data-filter');
      const cards = document.querySelectorAll('.lead-item');

      cards.forEach(card => {
        if (filter === 'all') {
          card.style.display = 'flex';
        } else if (filter === 'unread' && card.dataset.category === 'unread') {
          card.style.display = 'flex';
        } else if (filter === 'scheduled' && card.dataset.category === 'scheduled') {
          card.style.display = 'flex';
        } else if (filter === 'booked' && card.dataset.category === 'booked') {
          card.style.display = 'flex';
        } else {
          card.style.display = 'none';
        }
      });
    });
  });
